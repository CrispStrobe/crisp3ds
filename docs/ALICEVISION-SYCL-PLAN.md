# AliceVision SYCL/CPU build candidate (not yet built)

The post-merge upstream AliceVision revision `8e4f0be76b250f0dd04b11d2a9a457d59d71b42c` contains a `depthMap_sycl` library. Its CMake sets `ACPP_TARGETS=generic`, searches for AdaptiveCpp, and permits a SYCL-only depth-map backend. The minimum *dense-stage* CLI targets are `aliceVision_depthMapEstimation`, `aliceVision_depthMapFiltering`, and `aliceVision_meshing`; `aliceVision_prepareDenseScene` is additionally needed when beginning from AliceVision SfM data. These are source-supported targets, **not** a compiled or runtime-tested pipeline. See pinned [backend selection](https://github.com/alicevision/AliceVision/blob/8e4f0be76b250f0dd04b11d2a9a457d59d71b42c/src/CMakeLists.txt), [SYCL library](https://github.com/alicevision/AliceVision/blob/8e4f0be76b250f0dd04b11d2a9a457d59d71b42c/src/aliceVision/depthMap_sycl/CMakeLists.txt), and [pipeline targets](https://github.com/alicevision/AliceVision/blob/8e4f0be76b250f0dd04b11d2a9a457d59d71b42c/src/software/pipeline/CMakeLists.txt).

AdaptiveCpp revision `493644ef7024a6dc64ae103b890b80feb014c8c0` is a *candidate pin*, not a compatibility assertion. Its [installation guide](https://github.com/AdaptiveCpp/AdaptiveCpp/blob/493644ef7024a6dc64ae103b890b80feb014c8c0/doc/installing.md) requires the `full` compiler feature profile for `generic`, an official released LLVM 15–21 for that flow, and an installed compiler driver. The OpenMP CPU backend can run on a host CPU; an installed `acpp` plus generic compilation does **not** by itself prove that AliceVision's kernels execute correctly there. Avoid the `minimal`/`none` profiles. A Linux host with CMake ≥3.30, Ninja, compatible LLVM, Boost and the complete AliceVision native dependency set is the likely route. The pinned [AliceVision dependency checks](https://github.com/alicevision/AliceVision/blob/8e4f0be76b250f0dd04b11d2a9a457d59d71b42c/src/CMakeLists.txt) include Boost ≥1.76, OpenEXR ≥2.5, OpenImageIO ≥3.0, Expat, Eigen, Ceres, FLANN/lz4, CoinUtils/Clp/Osi, Lemon, Assimp and nanoflann, among others. This dependency closure has **not** been installed or sized for a hosted runner.

The checked candidate configure policy is `ALICEVISION_BUILD_DEPENDENCIES=OFF`, `ALICEVISION_USE_CUDA=OFF`, `ALICEVISION_USE_SYCL=ON`, `ALICEVISION_DEPTHMAP_BACKEND=SYCL`, SfM/MVS/CLI ON, tests and unrelated feature groups OFF. Turning the dependency builder off avoids AliceVision's top-level dependency-build branch but **does not prove** that nested CMake cannot download. Any future build must run configure/build with network denied after separately pinned/audited dependencies are present; fail if CMake attempts an external fetch. A scoped target build would use `cmake --build <build> --parallel 2 --target aliceVision_depthMapEstimation_exe aliceVision_depthMapFiltering_exe aliceVision_meshing_exe` only after configure succeeds. The exact command is a candidate, not tested here.

The read-only local audit is:

```sh
python3 -m scripts.metal_backend.sycl_preflight --workspace . \
  --alicevision /path/to/pinned/AliceVision \
  --adaptivecpp /path/to/pinned/AdaptiveCpp \
  --adaptivecpp-cache /path/to/AdaptiveCpp-build/CMakeCache.txt \
  --cache /path/to/AliceVision-build/CMakeCache.txt \
  --artifacts /path/to/AliceVision-build
```

It checks exact clean tracked source revisions and selected CMake markers, minimum local tool versions, the default local 10 GiB free-space floor (configurable with `--min-free-gib` for another host), explicit AliceVision and AdaptiveCpp cache settings, and one nonempty executable per expected dense target. It does not invoke configure/build, verify dependency provenance, inspect dynamic links, or execute kernels. `contract_met` only means those static contracts passed; `build_ready` remains unknown. The artifact check does not imply stage correctness. A later runtime gate would need a tiny licensed/hashed input scene, depth output count and finite-range checks, filtering output, nonempty triangulated mesh, source/command/environment hashes, and a separately labeled comparison with another backend. Registration or a nonempty mesh alone is not quality evidence.

License gate: [AliceVision says MPL-2.0 with additional component notices](https://github.com/alicevision/AliceVision/blob/8e4f0be76b250f0dd04b11d2a9a457d59d71b42c/COPYING.md); [AdaptiveCpp is BSD-style](https://github.com/AdaptiveCpp/AdaptiveCpp/blob/493644ef7024a6dc64ae103b890b80feb014c8c0/LICENSE). The AliceVision COPYING sentence calling CUDA “required for depth map computation” predates the pinned SYCL targets; do not use it to claim CUDA is needed for this source revision. Do not redistribute any combined binary until each selected dependency and dataset license is reviewed.

No build or download was run on the local M1. A GitHub-hosted Linux manual-dispatch job is conceivable but **not ready**: [GitHub lists 14 GB total SSD for standard Ubuntu runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), but actual free space and the required LLVM/AdaptiveCpp/AliceVision footprint remain unmeasured. The local 10 GiB reserve is not an inherent CI requirement; a CI budget needs its own explicit limit and measured starting capacity. First establish a pinned dependency manifest with sizes/licenses and an offline configure that passes under a disposable quota, then propose a time/disk-capped workflow without uploads or secrets. No workflow was added for this speculative path.
